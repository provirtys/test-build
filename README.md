# Система компонентов

## Включает в себя пакеты
- @integrity/base-ui (общие компоненты)
- @integrity/mobile-ui (для мобильных приложений)
- @integrity/tablet-ui (для планшетов)
- @integrity/web-ui (для веба)
- @integrity/desktop-ui (для десктопных приложений)
- @integrity/terminal-ui (для терминала сбора данных)
- @integrity/shared (общие для всех пакетов шрифты, иконки, хелперы, локаль, типы, стили, ...)

## Использование
Используется **pnpm workspace** для организации зависимостей.
```bash
pnpm i
```
Установит все необходимые зависимости. Обновление версий зависимостей происходит
в файле `pnpm-workspace.yaml` в разделе `catalog`

**Vite** для сборки пакетов перед публикацией.

Собрать все пакеты можно командой из корня проекта
```bash
pnpm build
```

В каждом пакете (не shared) будет папка `packages/*/dist/` с собранными файлами,
при публикации пакетов будет опубликованы только файлы из этой папки.

**Storybook** для демонстрации, документирования и тестирования компонентов.
Запуск storybook можно сделать в каждом пакете командой
```bash
pnpm storybook
```

Собрать статический storybook для всех пакетов из корня проекта:
```bash
pnpm build:storybook
```

В каждом пакете будет папка `packages/*/storybook-static/` с собранными файлами storybook.

**Biome** служит вместо lint и prettier, для webstorm есть специальный плагин, чтобы проверять код в IDE.
Можно использовать команды вручную:
```bash
pnpm lint
```
Пройдёт по всем файлам и подсветит все проблемы.

Для автоматической проверки используется **husky** для git hooks проверяющий код перед каждым commit.

⚠️ Перед запуском любого не базового пакета (base-ui) необходимо заранее собрать его. То же самое делаем и при появлении
изменений в базовом пакете

### Уровни компонентов
Каждый пакет внутри себя разделяет компоненты на несколько уровней:

1. ui
2. Elements
3. Block
4. Complexes
5. Layouts
6. Pages

Они нужны для более организованной и упрощенной разработки.

### Таблица использования компонентов по уровням

| Уровень → Может использовать ↓ | ui | elements | blocks | complexes | layouts | pages |
|---|---|---|---|---|---|---|
| **ui** | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| **elements** | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| **blocks** | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ |
| **complexes** | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ |
| **layouts** | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ |
| **pages** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

#### Принцип:
✅ - Компоненты могут использовать компоненты уровня **не выше**, чем они сами (то есть ниже или из своего уровня)   
❌ - Компоненты **не могут** использовать компоненты с **более высоких уровней**

### Уровень ui
Универсальные переиспользуемые компоненты

#### Характеристики:
* Не содержат бизнес-логику
* Максимально переиспользуемые
* Имеют префикс `V` (`VButton`, `VInput`, `VAlert`)
* 
#### Может использовать: `ui`

### Уровень Elements
Небольшие компоненты с проектной логикой и стилизацией

#### Характеристики:
* Могут содержать небольшую логику
* Стилизация специфична для проекта
* Комбинируют ui-компоненты

#### Может использовать: `ui` и `elements`

### Уровень Blocks
Более крупные части интерфейса с конкретным функционалом
#### Характеристики:
* Содержат бизнес-логику
* Могут работать с данными
* Имеют четкую функциональную роль
#### Может использовать: `ui`, `elements` и `blocks`

### Уровень Complexes
Комплексные решения, объединяющие несколько блоков

#### Характеристики:
* Высокая сложность логики
* Управление состоянием
* Взаимодействие между частями

#### Может использовать: `ui`, `elements`, `blocks` и `complexes`

### Уровень Layouts
Структурная организация контента на странице

#### Характеристики:
* Определяют общую структуру страницы
* Содержат навигацию и общие элементы
* Могут включать логику роутинга

#### Может использовать: `ui`, `elements`, `blocks`, `complexes` и `layouts`

### Уровень Pages
Конкретные страницы с уникальным контентом

#### Характеристики:
* Содержат специфичный для страницы контент
* Управляют загрузкой данных
* Могут содержать SEO-данные
* Связаны с роутингом
* ⚠️ Страницы из этого уровня не экспортируются, они только для внутреннего использования - файл src/pages.ts

#### Может использовать: все уровни

### Иконки

Все иконки для использования лежат в пакете `packages/shared/assets/icons`

Сборщик автоматически проходится по этой папке и создает один svg sprite.

Чтобы отобразить иконку из этого спрайта, нужно использовать компонент `VIcon` из этого же пакета и передать prop name со значением имени нужной иконки.

Например:
`<v-icon name='aggregation' size='40' />` - отобразит иконку размером 40x40 px.

## Создание папки для компонента из шаблона

Для облегчения создания нового компонента можно использовать следующую команду:

```code
pnpm create:componentFolder <НАЗВАНИЕ КОМПОНЕНТА> <ПУТЬ СОЗДАНИЯ>
```

Например:

```code
pnpm create:componentFolder MyComponent .\packages\desktop-ui\src\components\element\
```

Данная команда создаст папку с шаблонными файлами по указанному пути и добавит их в отслеживание в гите

Для каждого новосозданного компонента нужно добавить экспорты в `src/index.ts` текущего пакета

Например:

```code
export * from '@/components/element/MyComponent';
```

## Начало работы с пакетом в приложении

### 1. Установка зависимостей

Установите следующие зависимости: `quasar`, `@integrity/base-ui`, `@integrity/shared` и другой не базовый пакет

```bash
pnpm i quasar @integrity/base-ui @integrity/[НАЗВАНИЕ ПАКЕТА]
```

### 2. Подключение иконок

Для отображения иконок нужно дополнительно установить любой плагин для создания svg sprite и настроить его на папку
`node_modules/@integrity/shared/assets/icons`  
   Пример настройки плагина `@pivanov/vite-plugin-svg-sprite`:

```code
import svgSpritePlugin from '@pivanov/vite-plugin-svg-sprite'

export default defineConfig(() => {
    return {
    ...
        vitePlugins: [
            svgSpritePlugin({
              iconDirs: ['node_modules/@integrity/shared/assets/icons'],
              symbolId: 'icon-[name]',
              svgDomId: 'svg-sprite',
              inject: 'body-last',
            }),
      ],
    }
}
```

### 3. Подключение стилей

В preview.ts файле нужно подключить следующие файлы:

* Стили quasar

```code
@quasar/extras/material-icons/material-icons.css';
@quasar/extras/material-icons-outlined/material-icons-outlined.css';
@quasar/extras/material-symbols-outlined/material-symbols-outlined.css';
quasar/dist/quasar.css';
```

* Стили пакетов
```code
@integrity/shared/reset.css - файл сброса стилей (⚠️ подключать только в preview.ts, иначе переопределит стили quasar)
@integrity/base-ui/style.css - файл стилей базового пакета
@/css/main.scss - файл стилей текущего пакета (⚠️ подключать обязательно, хотя бы пустой, иначе не подтягиваются цвета quasar)
```

В vite.config.ts нужно подключить файл стилей из пакета `@integrity/shared`

```code
import { defineConfig } from 'vite';

export default defineConfig({
  ...
  css: {
    preprocessorOptions: {
      scss: {
        additionalData: `
          @import '@integrity/shared/style.scss';
        `,
      },
    },
  }
})
```

Таким образом, стили, шрифты и иконки из библиотек будут добавлены в проект, а также IDE подхватит scss переменные и
миксины
